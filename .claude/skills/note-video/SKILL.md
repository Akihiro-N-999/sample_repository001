# note記事 → 寸劇アニメ動画（オーケストレーター手順）

あなた（本体）はオーケストレーターとして、工程の順番、担当への受け渡し、人の確認（ゲート）を受け持つ。制作物の中身は各担当のサブエージェントに作らせ、本体で書き直さない。

**大原則：あとの工程ほど直すのが高くつく。** 台本が確定する前にアニメーションに手を付けない。各ゲートでは、人が了承するまで次の工程に進まない。

**読み上げは文の途中で切らない。** 台本の1行＝合成1回＝`tl.say()` 1回。字幕の改行やページ送りはエンジンが表示だけで行う。字幕に合わせて台詞を分けた制作物は、どの工程で見つけても差し戻す。

**尺は8分以上が標準。** 8分30秒〜10分で作る（`video/STYLE.md` の「尺と構成の標準」）。8分未満の企画は G1 に出さず、企画担当に戻す。

**ファイル名は `名前_v番号`。** 生成する画像・動画・音声は作り直すたびに番号を上げ、上書きしない（`video/STYLE.md` のファイル名のルール）。人に渡す成果物も番号付きの名前で送る。

## チームとモデル

| 役割 | サブエージェント | モデル | 理由 | 書くもの（`video/episodes/<slug>/`） |
|---|---|---|---|---|
| オーケストレーター | 本体 | セッションのモデル | 全体の判断と人とのやりとり | status.md |
| 企画 | `video-planner` | Opus | 何を伝えるかを決める工程で、ここがずれると全工程がやり直し | plan.md |
| 台本 | `video-scriptwriter` | Opus | 作者の文体と風刺の加減を保つ文章力が要る | script.md |
| キャラクター設定 | `video-character-designer` | Sonnet | 決まった選択肢（描画の引数・声の一覧）から選ぶ作業が中心 | characters.md |
| 音声・BGM | `video-sound-designer` | Sonnet | 数値の調整と、解析結果（秒数・読み）にもとづく判断が中心。聞こえ方の最終判断は人がする | sound.md |
| 内容校閲 | `video-content-reviewer` | Opus | 「何を言っているか・言ってよいか」。内容のずれや権利の問題は、見落とすと公開後に響く | review_content.md |
| 品質校閲 | `video-quality-reviewer` | Sonnet | 「どう聞こえるか・見えるか・台本どおりか」。チェック用スクリプトの結果と静止画を読む作業が中心 | review_quality.md |
| アニメーション制作 | `video-animator` | Sonnet | 量の多いコーディングと確認の繰り返し。手本のコードがあるので型に沿って書ける | episode.py |

モデルは各エージェント定義の `model:` で決まっている。

### 校閲の分担
- **内容校閲**：記事との一致、事実・数字・引用、作者の主張、字幕の文言の誤字、実在の企業・人物への配慮、著作権・規約・クレジット、YouTube の説明文。
- **品質校閲**：読み・アクセント、文の途中での切れ、台詞の長さ・速さ・無音・音割れ、音量バランス、字幕の表示、映像の崩れ、台本と実装の一致。機械的に測れるものは `video/lib/audio_check.py` で測る。
- どちらも制作物は直さず、指摘と「直す担当」を書く。範囲外の問題は「〜へ回す」欄に書くので、本体がもう一方に渡す。
- 2人の指摘がぶつかったとき（例：読みやすさのために文言を変えたい、など）は、内容校閲の判断を優先し、決めきれなければ人に聞く。

## ゲート（人の確認）

| ゲート | 時点 | 人に見せるもの | 了承で確定するもの |
|---|---|---|---|
| **G1 企画** | 企画のあと | 核となるメッセージ、尺の見積もり（寸劇・解説の内訳、8分以上か）、場面構成の表、新しい画像の枚数、トーン、省く内容、作者に求める実体験の材料 | 場面構成と尺 |
| **G2 台本と声** | 台本・キャラ設定・内容校閲・声の演出・品質校閲のあと | 台詞の一覧、キャラ表画像、**台詞の音声プレビュー（mp3）**、品質校閲の「人に聞いてほしい箇所」、内容校閲の「未確認」の項目 | 台詞・読み・配役・見た目・声の演出 |
| **G3 見本場面** | 見せ場1場面だけ作ったあと | その場面の静止画と短い動画（効果音・BGMつき）、BGMの候補と利用条件 | 絵柄・動き・テンポ・BGMの方向性 |
| **G4 公開前** | 全体制作・品質校閲・内容校閲のあと | 完成 MP4、2人の校閲結果、品質校閲の「人に聞いてほしい箇所」、YouTube のタイトル案と説明欄 | 公開してよい状態 |

ゲートでのふるまい：
- 見せるものは要点だけにする（長い md をそのまま貼らない）。ファイルは SendUserFile で送る。
- md（plan.md・script.md・characters.md など）を送るときは、`video/episodes/<slug>/versions/<名前>_v番号.md` に写しを作ってコミットし、写しのほうを送る。番号は `core.next_version()` と同じく、既存の最大の番号＋1。
- 了承の言葉（「OK」「進めて」など）をもらうまで、その回の応答を終えて待つ。
- 直しの指示をもらったら、下の「手戻りのルール」で戻り先を決め、どの工程をやり直すかを先に伝える。
- ゲートの結果は毎回 `status.md` に記録する。

## 工程

### 0. 準備（本体）
- 記事IDから slug を決める（英小文字とハイフン。例：`shovel`）。
- 記事を取得し `article.md` に保存する：`curl -s https://note.com/api/v3/notes/<記事ID>` の `data.name`（タイトル）と `data.body`（HTML）を、見出しと段落を残したテキストにする。有料部分がある記事や、作者がユーザー本人でない記事は、作業前にユーザーに確認する。
- VOICEVOX を起動しておく（`video/README.md`）。
- `status.md` を作る（形式は末尾）。すでにあれば、記録を読んで止まっている工程から再開する。

### 1. 企画 → G1
- `video-planner` を実行し、G1 を行う。

### 2. 台本とキャラクター設定（並行）
- `video-scriptwriter` と `video-character-designer` を同時に起動する（どちらも plan.md だけに依存する）。
- 両方終わったら、話者IDが script.md と characters.md で一致しているか本体で確かめる。ずれていれば台本担当に合わせさせる。
- キャラクター設定担当が画像生成指示書（`image_prompts.md`）を書いたら、**人に画像の生成をお願いする**。指示書の「必須」の画像だけを先に頼む。ファイル名は付けてもらわず、ダウンロードしたまま ZIP にまとめてアップロードしてもらう。
- 届いたら `python3 video/lib/intake.py list <ZIP>` で一覧画像を作り、本体が絵を見て指示書のどの画像か判断し、`mapping.json` に保存名（番号なし）と保存先を書いて `intake.py apply` で `名前_v番号` として保存する。判断に迷う画像は人に確かめる。生成を待つ間も台本の校閲と声の作業は進めてよい（画像が届くまでアニメーション制作には入らない）。
- 届いた画像は、品質校閲に一貫性（顔・眼鏡・髪・位置のずれ、背景の緑）を、内容校閲に文字や既存作品の要素がないかを確かめさせる。作り直しが必要な画像は、指示書の該当する指示文と理由を添えて人に頼む。
- シリーズ共通の人物（`video/characters/<id>/`）で画像がそろっていれば、この工程は省く。

### 3. 内容校閲（台本・キャラ）
- `video-content-reviewer` に plan.md / script.md / characters.md を article.md と突き合わせさせる。
- 「必須」の指摘は該当する担当に review_content.md を渡して直させ、再度校閲する。この往復は最大2回。残った指摘は G2 で人に判断を仰ぐ。

### 4. 声の演出と音声プレビュー → G2
- `video-sound-designer` を**工程A（声の演出）**で実行する。台本担当への差し戻し事項があれば台本担当に直させ、もう一度工程Aを行う。
- 本体で `python3 video/lib/voice_preview.py video/episodes/<slug>` を実行する（sound.md の調整が反映される）。
- `video-quality-reviewer` に**台詞の音声**の校閲をさせる（`audio_check.py voice` を実行し、読み・文の切れ目・長さ・速さ・無音を確かめる）。必須の指摘は直す担当（台本・音声）に渡し、直したら voice_preview と品質校閲をやり直す（最大2回）。
- mp3 とキャラ表画像、品質校閲の「人に聞いてほしい箇所」を送り、G2 を行う。**音声は人の耳で確かめてもらう**（エージェントは音を聞けない）。聞く場所は台詞番号で示して絞る。
- G2 の了承で、script.md・characters.md・sound.md の「台詞の調整」は確定する。

### 5. 効果音・BGMと見本場面 → G3
- `video-sound-designer` を**工程B（効果音・BGM）**で実行する。用意してほしい音源があれば、ファイル名と入手先をユーザーに伝える（BGM がそろわなくても先に進める）。
- `video-animator` を**見本段階**で実行する（見せ場の1場面を本体が指定する）。
- `video-content-reviewer` に sound.md の BGM・効果音の出どころと利用条件を確かめさせ、`video-quality-reviewer` に見本場面の静止画を見せる。それぞれの必須の指摘は直してから先へ進む。
- 静止画の一覧と `<slug>_sample.mp4` を送り、G3 を行う。BGM の候補と利用条件もここで確かめてもらう。
- シリーズで絵柄がすでに決まっていて、新しい背景や人物がないときは、G3 を省いてよいかを G2 でユーザーに聞く。

### 6. 全体制作と映像の校閲 → G4
- `video-animator` を**全体段階**で実行する。
- `video-quality-reviewer` に静止画の一覧と MP4 を見せる（`audio_check.py mix` で台本と実装の一致・音量バランス・字幕のページ送り・音量の基準、静止画で映像の崩れ）。必須の指摘は直す担当に渡す（最大2回）。
- YouTube のタイトル案と説明欄（記事リンク、VOICEVOX クレジット、合成音声を使っている旨）を本体で作る。
- `video-content-reviewer` にエンドカードのクレジット、タイトル・説明欄、G2 以降の台本の変更点を見せる。
- 2人の必須の指摘がなくなったら、MP4・タイトル案・説明欄・「人に聞いてほしい箇所」を送って G4 を行う。

### 7. 納品
- `video/episodes/<slug>/` の md と episode.py をコミットしてプッシュする（`video/out/` は含めない）。
- YouTube への投稿はユーザーが行う。

## 手戻りのルール

直しの指示を受けたら、まず戻り先を決めて、やり直す範囲をユーザーに伝えてから動く。

| 直したいこと | 直す担当 | やり直す範囲 |
|---|---|---|
| 場面の追加・削除・順番、尺 | 企画 | G1 からやり直し。G2 以降に出たときは、作り直しの範囲と手間を先に伝えて了承をもらう |
| 台詞の文言 | 台本 | 内容校閲と品質校閲（変更した台詞だけ）→ 変更した台詞の音声プレビュー → G2（差分だけ確認）→ 映像に出ていれば該当場面だけ作り直す |
| 台詞の読み | 台本（読み欄） | 品質校閲（変更した台詞だけ）→ 音声プレビュー → G2（差分だけ確認）→ 映像に出ていれば音声を差し替えて書き出し直す |
| 声の割り当て・見た目 | キャラクター設定 | 内容校閲（見た目の権利）・品質校閲（声）→ 音声プレビューかキャラ表 → G2（差分だけ確認）→ 該当する人物が出る場面を作り直す |
| 台詞ごとの話速・間・抑揚 | 音声・BGM（工程A） | 品質校閲（変更した台詞だけ）→ 音声プレビュー → G2（差分だけ確認）→ 映像に出ていれば音声を差し替えて書き出し直す（絵は直さない） |
| 効果音・BGM | 音声・BGM（工程B） | 内容校閲（音源の権利）→ アニメーション制作担当が書き出し直す → 品質校閲（音量バランス）→ G3 か G4 で再確認 |
| 絵・動き・テンポ・字幕の崩れ | アニメーション制作 | 該当場面だけ直して、品質校閲 → G3 か G4 で再確認 |

- 校閲の「必須」と人の指示がぶつかったときは、両方を並べて人に決めてもらう。
- 「変更した台詞だけ」の校閲では、校閲担当に変更前後の台詞番号と文言を渡し、ほかの台詞を見直させない。
- 確定済みのファイル（G2 以降の script.md・characters.md）を直すときは、status.md に「何を・なぜ」を記録する。

## status.md の形式

```
# 制作状況：<記事タイトル>
- 記事: <URL>
- slug: <slug>
- いまの工程: <例：5. 見本場面（G3 待ち）>

## ゲート記録
| ゲート | 日付 | 結果 | メモ |
|---|---|---|---|
| G1 企画 | 2026-11-14 | 了承 | 尺を4分に |

## 確定後の変更
| 日付 | ファイル | 変更 | 理由 |
|---|---|---|---|
```

## 報告のしかた
- 各工程の終わりに、ユーザーへ1〜2行で進み具合を伝える（例：「企画ができました。8場面・約4分です」）。
- 音声を耳で聞いて確かめていないこと、規約を確認できなかった項目は、そのとおりに伝える。
