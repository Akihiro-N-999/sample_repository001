# Web ページを安全に読む

初回の制作で、規約ページが読めなかったときに、証明書の検証を無効にするオプションを付けたコマンドを実行しようとした（安全確認で止められた）。原因は、正しい方法を試す前に近道を選んだこと。この環境では、検証を外さなくても読める。

## 手順
1. `python3 video/lib/fetch_page.py <URL> <保存先.txt>` を実行する。
   - まず curl で取得し、本文が短すぎれば、ヘッドレスのブラウザで表示して本文を取る。
   - どちらも、この環境のプロキシと証明書（CA）の設定をそのまま使う。ブラウザの信頼済み証明書にもプロキシの CA が登録済み。
2. 結果に応じて：
   - **終了コード 0**：保存した本文を読む。出典として使うなら URL と取得日を記録する。
   - **終了コード 2（許可されていないサイト）**：別の経路で取りにいかない。サブエージェントなら本体に「このドメインの許可が要る」と報告する。本体は get_environment → update_environment で許可を追加する（ユーザーの承認が要る）。リダイレクト先のドメイン（www なし、など）も許可が要ることがある。
   - **終了コード 3（証明書のエラー）**：検証を外さない。`/root/.ccr/README.md` の「certificate verify failed」の節に従い、ツールに CA（`/root/.ccr/ca-bundle.crt`）を指定する。
   - **終了コード 4（その他）**：サイトの障害（503 など）なら時間をおいて1回だけ再試行する。だめなら、ユーザーにブラウザで開いて確かめてもらう。
3. WebFetch ツールは、このセッションのネットワークの許可が効かない経路で動くことがある。名前解決エラーになったら、`fetch_page.py` に切り替える。

## やってはいけないこと（フックで止まる）
- 証明書の検証を無効にする：curl や wget の検証を外すオプション、ブラウザの証明書エラーを無視する設定、Python や Node.js で検証を外す設定、git の検証を外す設定。
- プロキシの設定を外す・空にする・使わない設定にする。
- 403/407（許可されていないサイト）を、別の経路や別のツールで取りにいく。

これらを含むコマンドやスクリプトは、`.claude/settings.json` のフック（`video/lib/hooks/block_insecure.py`）が実行前に止める。止められたら、迂回せずに上の手順に戻る。
