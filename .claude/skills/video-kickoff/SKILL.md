# 企画の前の準備（G1 のやり直しを減らす）

初回の制作では G1 を7回やり直した。原因は、動画の肝を確かめる前に企画を書かせたこと。次の順に進める。

1. `video-env` で環境を確かめる。
2. 記事を `video/episodes/<slug>/article.md` に保存し、`status.md` を作る（note-video の工程0）。
3. **ユーザーに次の4つを確かめる**（AskUserQuestion か、ふつうの質問で。推測で埋めない）。
   1. この記事の比喩で、いちばん伝えたいことは何か（例：スコップで掘るのは「自分の知識」）
   2. 寸劇は現実の職場の物語にするか（第一案）、寓話にするか。比喩は解説の「私にはこう見えていました」で見せる型でよいか
   3. 参考にしたい動画や構成の型があるか（例：寸劇7〜8割＋作者の短い解説）
   4. 実在の企業・人物につながる要素（社名をもじった名前、企業の色など）をどこまで許すか
4. 並行して次を動かす：
   - `video-content-reviewer` に**事実確認**をさせ、review_content.md に「台本で言える範囲」と「情報源の一覧」を作らせる（企画の前に）。
   - `video-researcher` に research.md を作らせる。
5. 3 の答え、事実確認、リサーチがそろってから `video-planner` を動かす。企画担当への指示に、3 の答えをそのまま書く。
6. 決まったことは status.md の「決定事項」に日付つきで書く。
